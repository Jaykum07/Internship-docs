# Day 08 — SQL Server + Entity Framework Core

## Goal
Understand how an ASP.NET Core API connects to SQL Server using Entity Framework Core, how CRUD operations work with a real database, how migrations work, and how to debug common EF Core/database errors.

## 1. Relational Database Fundamentals
- Database: persistent data storage.
- Table: stores related records.
- Row: one record.
- Column: one property/field.
- Primary key: uniquely identifies a record.
- Foreign key: connects related records.

Basic SQL:
- `SELECT` → read
- `INSERT` → create
- `UPDATE` → modify
- `DELETE` → remove
- `WHERE` → filter
- `ORDER BY` → sort
- `JOIN` → combine related tables

## 2. Why We Moved from List to Database
`List<Student>` is temporary in-memory storage. Data disappears when the application stops.

```text
ASP.NET Core
      ↓
   EF Core
      ↓
 SQL Server
      ↓
Persistent data
```

Important: `DbContext` does not permanently store data. SQL Server does.

## 3. Entity Framework Core
EF Core is Microsoft's ORM for .NET.

ORM = Object Relational Mapper.

```text
C# Objects
    ↕
EF Core
    ↕
SQL
    ↕
Database
```

Example:
```csharp
_context.Students.ToList();
```

## 4. Entity
Our `Student` class is an entity:

```csharp
public class Student
{
    public int Id { get; set; }
    public string Name { get; set; }
    public int Marks { get; set; }
}
```

Conceptually:
```text
Student class → Students table
Id → Id
Name → Name
Marks → Marks
```

## 5. DbContext and DbSet
We created:

```csharp
public class StudentDbContext : DbContext
{
    public DbSet<Student> Students { get; set; }

    public StudentDbContext(
        DbContextOptions<StudentDbContext> options)
        : base(options)
    {
    }
}
```

`DbContext` manages database interaction, querying, change tracking, and saving changes.

`DbSet<Student>` represents the Student entity collection/query interface.

`DbContextOptions` carries provider/database configuration into the context.

## 6. Dependency Injection
We registered:

```csharp
builder.Services.AddDbContext<StudentDbContext>(options =>
    options.UseSqlServer(
        builder.Configuration.GetConnectionString("DefaultConnection")));
```

The service receives the context through constructor injection:

```csharp
private readonly StudentDbContext _context;

public StudentService(StudentDbContext context)
{
    _context = context;
}
```

Flow:
```text
DI Container
 ↓
creates StudentDbContext
 ↓
StudentService receives it
 ↓
_context
```

## 7. Controller → Service → DbContext Architecture
```text
Client / Swagger / Postman
          ↓
   StudentController
          ↓
    IStudentService
          ↓
    StudentService
          ↓
    StudentDbContext
          ↓
       EF Core
          ↓
      SQL Server
```

Controller handles HTTP concerns: routing, request/response, status codes.

Service handles application/business logic and database operations through DbContext.

DbContext handles EF Core/database interaction.

## 8. Why Use an Interface?
The controller depends on `IStudentService`, not the concrete implementation.

```csharp
public StudentController(IStudentService studentService)
{
    _studentService = studentService;
}
```

This keeps the controller loosely coupled to the implementation.

## 9. EF Core CRUD

### GET All
```csharp
_context.Students.ToList();
```

`ToList()` executes the query and materializes the results as C# objects.

### GET by ID
```csharp
_context.Students
    .FirstOrDefault(s => s.Id == id);
```

If no student exists, it returns `null`. The controller can then return HTTP 404.

### POST
```text
POST
 ↓
Controller
 ↓
Service
 ↓
_context.Students.Add(student)
 ↓
EF marks entity as Added
 ↓
SaveChanges()
 ↓
SQL INSERT
 ↓
SQL Server
```

`Add()` marks the entity for insertion. `SaveChanges()` persists the change.

### PUT
```text
PUT
 ↓
Find entity
 ↓
If missing → 404
 ↓
Modify properties
 ↓
SaveChanges()
 ↓
SQL UPDATE
```

### DELETE
```text
DELETE
 ↓
Find entity
 ↓
Remove(entity)
 ↓
SaveChanges()
 ↓
SQL DELETE
```

Successful DELETE can return `204 No Content`.

## 10. Identity Primary Key
Our `Id` is generated by SQL Server.

We initially tried:

```csharp
student.Id = _context.Students.Count() + 1;
```

This caused:

```text
Cannot insert explicit value for identity column
when IDENTITY_INSERT is set to OFF.
```

The database owns identity generation, so the application should not manually assign the ID.

Correct flow:

```text
POST
 ↓
Name + Marks
 ↓
SQL Server
 ↓
SQL Server generates Id
```

## 12. Migrations
A migration is a versioned description of database schema changes.

Created with:
```powershell
dotnet ef migrations add InitialCreate
```

Applied with:
```powershell
dotnet ef database update
```

Migration describes a schema change; database update applies it.

A migration marked `(Pending)` exists but has not yet been applied.

EF tracks applied migrations in:
```text
__EFMigrationsHistory
```

## 15. LINQ Basics
Example:

## 16. Debugging EF Core Errors
When a 500 error occurs:

1. Find the exact exception.
2. Read the inner exception.
3. Find the file and line number.
4. Identify the failing layer.
5. Understand what the application expected.
6. Understand what EF/database expected.
7. Compare the assumptions.
8. Make the smallest reasonable fix.
9. Rebuild.
10. Reproduce and verify.

Our identity-column error followed exactly this process:
```text
500
 ↓
DbUpdateException
 ↓
SqlException
 ↓
Identity column error
 ↓
Application manually assigned Id
 ↓
SQL Server expected to generate Id
 ↓
Remove manual Id assignment
 ↓
POST works
```

## 17. Layer-Based Debugging
```text
HTTP / routing → Controller
Business logic → Service
EF/query/tracking → DbContext / EF Core
Schema/SQL → SQL Server / migrations
Configuration/DI → appsettings / DI / environment
```

## 18. Working with AI in a Real Project
Do not blindly ask AI to fix everything.

Better workflow:
1. Reproduce the error.
2. Read the stack trace.
3. Identify the failing layer.
4. Form your own hypothesis.
5. Ask AI to validate your reasoning.
6. Inspect the suggested change.
7. Understand why it works.
8. Apply the smallest fix.
9. Test it yourself.

Useful prompt:
> I'm getting this exception. Here is the stack trace. Tell me which layer is failing and what I should inspect first. Don't rewrite the whole feature.
